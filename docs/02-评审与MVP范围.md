# 方案评审结论与 MVP 范围（已锁定）

评审时间：2026-10-27 · 2026-10-28 完成实现审查并复核锁定决策（见 [04-审查与路线图.md](04-审查与路线图.md)）

## 一、总体结论

方案技术路线成立——感知哈希、并查集、增量缓存都是被验证的经典做法，Tauri 2 选型合适。修正以下问题后进入开发。

## 二、评审发现的问题与修正

### 1. LSH 分桶与默认阈值矛盾 → 会漏报（算法硬伤）

4×16 分桶的鸽巢原理只在阈值 ≤3 时成立；默认阈值 ≤5 时，两个哈希的差异可分散为 2+1+1+1——四段全不同，相似对被漏掉。结果"看起来正常"，只是悄悄少报重复，最隐蔽。

**修正**：真实照片库规模（1–10 万张）下不需要 LSH——64 位汉明**暴力两两比对**：popcount 单条 CPU 指令，5 万张 ≈ 1.25×10⁹ 对 ≈ 3 秒单核、rayon 并行 <1 秒、内存 800KB。MVP 采用暴力比对（约 20 行代码、零漏报）；将来超过 20 万张再换 BK-tree（天然支持任意阈值、无漏报），放弃分段 LSH。

### 2. 并查集单链接 → 链式合并（结果质量）

A≈B、B≈C 归组后，A 与 C 距离可达 2×阈值——组内出现"完全不像"的照片，打击信任。

**修正**：聚类后做**组内一致性校验**（组通常 ≤10 张，两两校验成本可忽略），组内最大距离超界即拆组。

### 3. HEIC 成本被低估（工程）

libheif 是 C 库，Windows 侧要 vcpkg + 捆绑 DLL，CI 复杂度上一个台阶；macOS 可走系统 ImageIO，零 C 依赖。→ HEIC 决策与平台决策绑定。

### 4. EXIF 校正必须留，翻转容错可以砍

竖拍误判高频（必须）；镜像版本低频且每张 ×2 哈希、×4 比对量。翻转容错推迟到 v1.1。

### 5. 缩略图走 IPC 会卡死 webview

结果页可能上千组×多图，base64 过 IPC 必卡。**必须在 Rust 侧生成缩略图落盘缓存，前端用 Tauri asset 协议直连加载 + 虚拟滚动。**

### 6. 云端占位文件

OneDrive/iCloud"优化存储"的占位文件会解码失败甚至触发后台下载。识别 offline/reparse 属性直接跳过，文案中说明与"绝不联网"承诺的关系。

### 7. 48 小时不现实

原型可以；含双平台打包、未签名绕过指引、落地页的可发布产品，现实是 1.5–2 周业余时间。macOS 未签名 dmg 在新系统直接报"已损坏"，普通用户不会执行 `xattr -cr`——签名/公证时间要预留，或首发只发一个平台。

### 8. 小项

- 精确去重用 **blake3** 替代 SHA-256（快 3–5 倍，非安全场景足够）
- SQLite 缓存键（路径+mtime+size）设计正确，保留
- ~~dHash 默认阈值 ≤5 偏敏感~~ → 实现已升级为 **pHash + 颜色签名双闸门**，三档阈值经真实样本校准（19 张真实照片 + 8 种变换变体，共 3500+ 对）

## 三、已锁定的 MVP 决策（2026-10-28 复核更新）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 首发平台 | **仅 macOS** | HEIC 走系统 ImageIO 零 C 依赖；避开 Windows 签名/SmartScreen；苹果用户付费意愿高 |
| CPU 架构 | **仅 Apple Silicon 首发** | 当前只验证过 arm64；Intel/Universal 视 v1.1 需求再加 |
| HEIC | **MVP 硬要求，仅 macOS**（ImageIO 实现） | iPhone+Mac 核心人群的差异化卖点；完成前文档如实标注「仅精确去重」 |
| 撤销 | **纳入 MVP：8 秒应用内撤销**（2026-10-28 改，原定 v1.1） | 已实现；发布前改造为后端批次 ID 授权，前端不再回传可信路径 |
| 相似默认勾选 | **仅「完全相同」默认勾选；「仅相似」必须手动选** | 误聚时默认删除风险过高；误删恐惧是品类头号转化杀手 |
| 分发 | **公开发布：Developer ID 签名 + 公证**（从 v1.2 提前到首发） | 未签名 DMG 在新系统直接报「已损坏」，普通用户不会 xattr 绕过 |
| 性能验收 | **50,000 张为验收规模；100,000 张仅压测** | 50k 暴力比对 <1s 可信；100k 不再对外承诺「<1 秒」 |
| 付费 | **完全免费** | 验证期零摩擦，先积累信任、口碑和真实反馈 |

## 四、MVP 功能清单

**包含**：
- 选择单个文件夹（含子目录开关）
- 格式：JPEG / PNG / WebP / BMP / GIF / HEIC(macOS)
- 精确去重（大小分桶 → blake3）+ 相似去重（pHash + 颜色签名双闸门，EXIF 校正，暴力比对 + complete-link 拆组）
- SQLite 增量缓存（二次扫描只算新文件）
- 结果页：分组列表（大结果集滚动性能以 1000 组实测验证）+ asset 协议缩略图 + 勾选
- 保留最优自动勾选（分辨率 → 大小 → EXIF → 时间）；默认删除勾选仅覆盖「完全相同」项，「仅相似」须手动选
- 相似度三档预设（严格/均衡/宽松，切换秒级重聚类）
- 进度 + 实时计数
- 移废纸篓 + 二次确认 + 8 秒应用内撤销；跳过 OneDrive/iCloud 占位文件

**明确不做（纪律）**：翻转容错、设置页（硬编码合理默认）、多文件夹、过滤规则、付费授权、Windows 版。

## 五、优先级（2026-10-28 实现审查更新）

原 P0 核心闭环已跑通（Rust 54 项测试 + UI 冒烟通过）。当前优先级以 [04-审查与路线图.md](04-审查与路线图.md) 为准：

- **P0（发布阻断）**：删除安全边界（IPC 授权 + 文件身份校验）、HEIC（ImageIO）、云占位保护、缓存键精度、签名公证
- **P1**：相似默认不勾选、大图对比、聚类规模上限与 50k 基准、错误可见性、大结果集滚动实测
- **P2**：清理策略、可访问性、杂项收口

## 六、迭代路线

- **v1.0 (MVP)**：单文件夹扫描 → 分组 → 废纸篓 + 8 秒撤销；HEIC（ImageIO）；Developer ID 签名公证；仅 Apple Silicon
- **v1.1**：镜像容错、撤销批次队列、Intel/Universal 支持（视需求）
- **v1.2**：多文件夹、过滤规则、自定义保留策略
- **v2**：变现（Paddle/爱发电 + 离线 HMAC license）+ Windows 版
