## 三、风险清单

### P0（发布阻断）

1. **破坏性 IPC 无后端授权**：`trash_files` 接受任意路径；`restore_files` 信任前端回传的路径与废纸篓路径；阈值接受任意整数。
2. **删除前不校验文件身份**：预览后同路径文件被替换时，会把新文件移入废纸篓（TOCTOU）。
3. **HEIC 承诺未兑现**：扫描器接收 HEIC，但 `image` crate 未启用 HEIC 解码，相似识别与缩略图均不可用。
4. **云占位文件保护不足**：仅按 `size == 0` 判断；dataless/ubiquitous 文件读取时仍可能触发 iCloud/OneDrive 下载，违背「绝不联网」。
5. **分发链路不可用**：DMG 打包失败（Finder AppleScript -10006）；应用仅 ad-hoc 签名；无公证。
6. **缓存正确性不足**：mtime 截断到秒、无算法版本号；同秒同大小替换文件会命中旧指纹。

### P1（核心质量与体验）

- 「仅相似」默认勾选删除（决策 #2 已定为修复项）
- 聚类最坏情况平方级时间与内存（物化全部 pair + complete-link 方阵）
- 缩略图未应用 EXIF 方向，竖拍预览可能旋转错误
- 结果页无大图对比，小缩略图不足以安全判断「仅相似」
- 切换相似度档位会重新读取文件计算精确哈希（精确哈希未缓存）
- 遍历 / 解码 / 哈希 / 缩略图错误大多静默忽略；隐藏目录实际仍被递归
- regroup 与删除可并发，旧响应可能覆盖新状态；批次日志按秒命名可能覆盖
- `content-visibility: auto` 是否扛得住 1000 组未实测
- 无 CI、无统一 check 脚本、clippy 21 项未清零

### P2（维护与一致性）

- 文档漂移（本次已同步：dHash→pHash+颜色签名、trash crate→Foundation、撤销入 MVP）
- 缩略图 / 批次日志无清理策略
- 模态框缺焦点管理与 Escape；git 对象库有临时垃圾对象

## 四、实施路线（按依赖排序）

### 阶段 1：删除安全边界

目标：任何前端输入都无法让后端操作未预览、已变化或越界的文件。

- 后端签发 `scan_id` / 不透明 `file_id` / `batch_id`；前端不再回传可信路径
- 删除前校验 device + inode + size + mtime_ns；阈值改为后端三档枚举
- 扫描 / regroup / 删除 / 恢复引入 generation，过期响应不得覆盖新状态
- 移除未使用的 `plugin-opener` 依赖与权限

验收：伪造路径、文件替换、伪造批次、非法阈值全部被拒绝并有测试；54 项既有测试不回退。

### 阶段 2：格式与缓存正确性

目标：兑现 HEIC 与「绝不联网」承诺，缓存不返回旧内容。

- 统一 `decode_image` 边界：普通格式走 `image`，HEIC/HEIF 走 macOS ImageIO（指纹与缩略图共用）
- 用 macOS 原生属性识别 dataless / ubiquitous / 未下载文件，打开前跳过并统计原因
- 缓存键升级 mtime_ns + 文件身份 + 算法版本；缩略图键加方向与版本
- 缩略图应用 EXIF 方向；隐藏目录用 `filter_entry` 阻止递归

验收：真实 HEIC 可相似识别且预览方向正确；云占位测试不触发任何读取；同秒替换文件必定缓存失效。

### 阶段 3：误删防护与规模验证

目标：用户有足够信息安全决策，目标规模下不失控。

- 「仅相似」默认不勾选（决策 #2）；大图对比、完整路径 / 尺寸 / 格式展示
- 先按精确哈希折叠等价类再进感知聚类；为候选数与大簇规模设上限
- 10k / 50k / 100k release 基准（延迟、内存、取消响应）；1000 组 DOM 实测，不达标再上真虚拟列表
- 扫描页展示跳过 / 失败统计；错误不再静默

验收：50k 达标（决策 #6）；取消延迟有上限；相似项默认不选；1000 组滚动流畅。

### 阶段 4：测试与发布工程

目标：产出可安装、可验证、可回归的 macOS 包（决策 #4 / #5）。

- 新增 IPC 授权 / TOCTOU / HEIC / 云占位 / 并发乱序集成测试；真实 Tauri E2E
- 统一脚本：`check`（fmt + clippy 清零 + test + build）、`test:ui`、`bundle:verify`
- 解决 DMG 打包失败（必要时改 `hdiutil -srcfolder`）；Developer ID 签名、公证、staple、`spctl --assess`
- 两台真实 Apple Silicon Mac 验证 HEIC / 废纸篓 / 撤销 / 安装与首次启动

验收：一条命令完成构建→测试→签名→公证→验证；`codesign --verify --strict` 与 `spctl` 通过。

### 阶段 5：文档与发布收口

目标：承诺、实现、验收完全一致。

- README / 01 / 02 / 03 与实现保持一致（以本文档为准）
- 明确 HEIC 能力边界、云占位行为、系统要求（Apple Silicon、macOS 版本下限）、已知限制

验收：所有文档无互相冲突的能力声明；发布 Checklist 全部可执行验证。

## 五、明确暂不做（防过度设计）

- 不拆微服务 / 事件总线 / CQRS / Redis / 通用 Repository / DI 框架
- 不立即上 BK-tree / LSH / GPU：先折叠精确等价类 + 设上限 + 实测，超 20 万张再迁移
- 不做 HEIC 全平台抽象（libheif/Windows），先把 macOS ImageIO 路径做对
- 不在分发渠道确定前仓促开启 App Sandbox（首发为非沙箱公证 DMG）
- 不为单扫描任务引入连接池 / WAL / 迁移框架
