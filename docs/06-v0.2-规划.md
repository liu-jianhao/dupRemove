# v0.2.0 规划（下一版 Release）

> **当前线：** [v0.1.0](https://github.com/liu-jianhao/dupRemove/releases/tag/v0.1.0) 已发布（预览）。  
> **下一 tag：** **v0.2.0** — 体验与工程收口，仍属预览线；**v1.0.0** 留作「正式 MVP」里程碑（见文末）。

## 定位

v0.1 已具备完整主路径（扫描 → 分组 → 废纸篓 → 撤销）。v0.2 不扩功能面，优先：

1. 让**陌生人**能装、能懂、敢用（安装说明、预览图、可访问性）。  
2. 让**仓库**可回归（CI、文档与实现一致）。  
3. 控制**磁盘**与**边角体验**（缓存清理、确认框键盘）。

分发仍为 **GitHub Release + ad-hoc DMG**（不阻塞 v0.2）；Developer ID 公证放入 v1.0 可选项。

## 明确不做（v0.2 纪律）

与 [02-评审与MVP范围.md](02-评审与MVP范围.md) 一致：多文件夹、设置页、Intel 包、镜像容错、Windows、付费 — **全部 v1.1+**。

## 发版验收（v0.2.0）

```bash
npm run check
npm run test:ui
npm run capture:assets   # 可选但 README 需要则必跑
npm run release
```

- [ ] CI 通过  
- [ ] 真机冒烟勾选完成  
- [ ] tag `v0.2.0` + GitHub Release 附 DMG  
- [ ] README 路线图「已发布」行更新为 v0.2.x  

## v1.0.0 与 v0.2 的关系

| 版本 | 含义 |
|---|---|
| **v0.2.x** | 预览迭代：工程 + 体验 + 文档，功能集≈v0.1 |
| **v1.0.0** | 正式 MVP：在 v0.2 基础上 **承诺冻结** — 双机验收、对外声明与实现一致；**可选** Developer ID 公证（不办则继续 ad-hoc + 安装说明） |

v1.0 不发新大功能，只发「敢对外说 MVP 完成」的信号。

## 建议实施顺序（开发）

1. CI（半天）  
2. 模态键盘 / 焦点（小）  
3. capture:assets + README 预览（小）  
4. 真机走一遍并打勾（人工）  
5. 缩略图清理（中，可最后砍到 v0.2.1）  
6. tag **v0.2.0** → Release
